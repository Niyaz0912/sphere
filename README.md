# Сфера — платформа онлайн-записи и CRM для бизнеса

**Сфера** — это Django-приложение, в котором небольшая компания или частный
мастер получает публичную страницу с прайсом и онлайн-записью, а в рабочем
кабинете ведёт воронку заказов, клиентскую базу, оплаты и аналитику.

Один проект — много независимых компаний: клиенты, услуги, этапы воронки и
заказы полностью изолированы по `owner` (пользователю Django).

```
Сфера (Sfera)
├── Главная площадки              /                 — без входа
├── Рабочий стол компании         /dashboard/
├── Публичная страница компании   /s/<slug>/        — без входа
├── Клиенты и история             /clients/
├── Услуги и прайс                /services/
├── Аналитика                     /analytics/
└── Настройки страницы и воронки  /settings/
```

Старые адреса `/m/<slug>/` навсегда перенаправляются на `/s/<slug>/`.

## Возможности

- **Публичная главная площадки** `/` — описание сервиса, кнопки «Создать
  страницу бизнеса» и «Войти», витрина компаний. В витрину попадают только
  профили с включённой галочкой `is_public` (по умолчанию `True`).
- **Публичная страница компании** `/s/<slug>/` — название, описание, адрес,
  телефон, Telegram, часы работы и прайс только активных услуг. Четыре темы
  оформления: `blue`, `dark`, `rose`, `emerald`.
- **Единая форма записи** — имя и фамилия, телефон, дата и время, кнопка
  «Записаться». Кнопка рядом с услугой открывает форму с уже выбранной услугой,
  общая кнопка «Записаться» в шапке позволяет выбрать услугу из списка.
- **Онбординг без демо-мусора** — новый аккаунт создаётся с пустой базой услуг,
  клиентов и записей. После регистрации мастер попадает на `/services/` с
  подсказкой «Шаг 1: Создайте хотя бы одну услугу…».
- **Публичная ссылка под рукой** — на `/dashboard/` и `/services/` есть карточка
  с адресом `/s/<slug>/`, кнопками «Скопировать ссылку» и «Открыть страницу
  глазами клиента».
- **Воронка (канбан)** — настраиваемые этапы, суммы по колонкам, быстрый перевод
  на следующий этап, редактирование записи и приём оплаты в модальных окнах.
- **Список / расписание** — фильтры «Сегодня», «Завтра», «Все активные»,
  «Завершённые» и кнопка «Принять оплату» прямо в строке.
- **Умный помощник** — до трёх карточек-подсказок:
  1. неоплаченный остаток на финальных этапах;
  2. заявки без движения больше 3 дней на промежуточных этапах;
  3. «спящие» клиенты с последним визитом больше 90 дней назад и готовый текст
     напоминания для копирования в мессенджер.
- **Клиенты** — мгновенный поиск по имени, телефону и идентификатору
  (гос. номер, VIN, модель техники), карточка с хронологией работ, материалов и
  общей суммой денег за всё время.
- **Услуги** — управление в модалках, цена, себестоимость расходников,
  длительность, публикация на странице, Excel-экспорт, шаблон и импорт.
- **Аналитика** — сегодня / неделя / месяц: выручка по `paid_amount`, чистая
  прибыль, разбивка наличные/карта, средний чек, долги и топ-5 услуг.
- **Без интернета** — Bootstrap 5 лежит в `static/vendor/bootstrap/`, шрифт
  системный, все SVG-иконки и логотип встроены локально, CDN не используется.

## Быстрый старт

```powershell
python -m venv .venv
.venv\Scripts\python.exe -m pip install -r requirements.txt
.venv\Scripts\python.exe manage.py migrate
.venv\Scripts\python.exe manage.py seed_demo
.venv\Scripts\python.exe manage.py runserver
```

macOS / Linux:

```bash
python3 -m venv .venv
source .venv/bin/activate
pip install -r requirements.txt
python manage.py migrate
python manage.py seed_demo
python manage.py runserver
```

Откройте **http://127.0.0.1:8000/**. Это публичная главная площадки; компании
из витрины ведут на свои страницы записи.

### Демо-доступ

```
Логин:  admin
Пароль: admin123
Рабочий стол: http://127.0.0.1:8000/dashboard/
Страница компании: http://127.0.0.1:8000/s/demo-service/
```

`seed_demo` создаёт одну цельную демо-компанию **Автосервис «Сфера»**:

- воронку из 5 этапов: «Новая заявка» → «Замер / Осмотр» → «Предоплата» →
  «В работе / Изготовление» → «Выполнено»;
- 5 услуг автосервиса: замена масла, компьютерная диагностика, шиномонтаж,
  полировка кузова, развал-схождение;
- 3 клиентов с гос. номерами автомобилей;
- 8 заказов на разных этапах, с оплатами, долгом, историей работ и «зависшей»
  заявкой — чтобы все три подсказки умного помощника были видны сразу.

Команда идемпотентна: повторный запуск не дублирует заказы, услуги и клиентов.

### Быстрый сброс пароля администратора

Двойной щелчок по `reset_password.bat` (или `python reset_admin_password.py`)
создаёт/обновляет пользователя `admin` с паролем `admin123` и его профиль.

## Онбординг нового бизнеса

1. Мастер регистрируется на `/accounts/register/`: логин, пароль, название
   компании и шаблон воронки.
2. Создаются профиль, публичный адрес и этапы воронки. **Услуги, клиенты и
   записи не создаются** — база пустая.
3. Мастер сразу попадает на `/services/`, где видит шаг 1 и кнопку добавления
   услуги.
4. Публичная ссылка `/s/<slug>/` уже доступна; на рабочем столе вместо
   «Создать запись» показывается «Сначала добавьте услуги», пока прайс пуст.

## Архитектура данных

### `core`

| Модель | Поля |
|---|---|
| `MasterProfile` | `user` (OneToOne), `slug` (unique), `business_name`, `description`, `phone`, `telegram`, `address`, `theme`, `work_hours`, `is_public` |
| `Client` | `owner`, `name`, `phone`, `identifier` (гос. номер/VIN/модель), `notes`, `created_at` |

`MasterProfile` создаётся сигналом `post_save` при регистрации пользователя.
Вместе с профилем автоматически создаются базовые этапы воронки. Для аккаунтов,
созданных до появления профиля, `MasterProfile.for_user()` создаёт его лениво.

`is_public` по умолчанию `True`: компания сразу появляется в витрине `/`.
Галочку можно снять в настройках.

### `shop`

| Модель | Поля |
|---|---|
| `PipelineStage` | `owner`, `name`, `order`, `color` (`primary/warning/info/success/secondary`), `is_final` |
| `Service` | `owner`, `name`, `price`, `cost_price`, `duration_minutes`, `is_active` |
| `Order` | `owner`, `client`, `service` (nullable), `service_name` (снимок), `stage`, `scheduled_at`, `total_amount`, `paid_amount`, `payment_method`, `work_details`, `created_at`, `updated_at` |

Свойство `Order.debt_amount = total_amount - paid_amount`; `Order.cost_amount` и
`profit_amount` считаются по текущей себестоимости услуги.

**Изоляция данных.** Каждый queryset в представлениях фильтруется
`owner=request.user`, а объекты берутся через
`get_object_or_404(..., owner=request.user)`. Чужой клиент, заказ или услуга
возвращают 404 — даже при ручной подстановке id.

### Шаблоны воронки

| Шаблон | Этапы |
|---|---|
| Быстрые услуги | Новая заявка → Подтверждено → В работе → Выполнено |
| Сложные заказы / Изготовление | Новая заявка → Замер / Осмотр → Предоплата → В работе / Изготовление → Выполнено |

В настройках шаблон можно «догрузить»: недостающие этапы добавятся, этапы без
заказов убираются, а этапы с историей сохраняются. Полная замена воронки
выполняется только пока у компании нет заказов.

## Как работает онлайн-запись

1. Клиент открывает `/s/<slug>/` и видит прайс активных услуг.
2. Нажимает «Записаться» рядом с услугой — форма прокручивается к записи и
   услуга уже выбрана. Либо нажимает общую кнопку «Записаться» в шапке и
   выбирает услугу в той же форме.
3. Указывает имя и фамилию, телефон, дату и время (не в прошлом и не дальше
   180 дней).
4. Сервер ищет клиента компании по телефону (сравнение по последним 10 цифрам),
   создаёт нового при необходимости и ставит заказ на первый этап воронки с
   ценой услуги.
5. Показывает экран успеха `?booked=1`. Скрытое honeypot-поле защищает форму от
   простых ботов.

Внизу публичной страницы — футер «Онлайн-запись работает на платформе Сфера» со
ссылкой на главную.

## Умный помощник

Правила находятся в `shop/assistant.py` и не используют внешний AI:

| Правило | Условие | Действие |
|---|---|---|
| Долги | `stage.is_final=True`, `total_amount > paid_amount` | ссылка на завершённые записи |
| Зависшие | `stage.is_final=False`, `updated_at` старше 3 дней | ссылка на активные |
| Спящие | последняя запись клиента старше 90 дней | текст напоминания + копирование |

## Аналитика

- **Выручка** — сумма `paid_amount` по заказам, дата визита которых попадает в
  выбранный период.
- **Чистая прибыль** — выручка минус себестоимость материалов по тем визитам, где
  уже была оплата.
- **Средний чек** — выручка / количество оплаченных визитов.
- **Разбивка** — наличные и карта по фактически внесённым суммам.
- **Топ-5 услуг** — по выручке, с количеством записей и прибылью.
- **Долги** — остаток по всем записям периода.

Себестоимость берётся из текущего прайса услуги (отдельного снимка в заказе нет).

## Excel-обмен прайсом

Колонки файла `.xlsx`:

| Название | Цена | Себестоимость | Длительность, мин | Активна |
|---|---|---|---|---|
| Замена масла | 3500 | 1800 | 60 | да |

- совпадение по названию (без учёта регистра) обновляет услугу;
- новое название создаёт услугу;
- пустые строки пропускаются;
- ошибки попадают в отчёт с номером строки и причиной.

## Дизайн

- фон `#F8FAFC`, карточки `#FFFFFF` с рамкой `1px solid #E2E8F0` и радиусом `12px`;
- основной цвет интерфейса `#2563EB`, логотип — синий круг `#1e50c8` с
  наклонённой разомкнутой орбитой и белой точкой;
- шрифт `system-ui, -apple-system, "Segoe UI", Roboto, sans-serif`;
- публичные темы переключают CSS-переменные `--pub-*`;
- мобильные таблицы превращаются в карточки, канбан прокручивается по горизонтали.

## Ограничения

- SQLite рассчитан на небольшой сервис; для продакшена с высокой нагрузкой лучше
  PostgreSQL.
- Уведомления (SMS/Telegram) не отправляются автоматически — помощник готовит
  текст, отправка остаётся за компанией.
- `paid_amount` не имеет отдельной даты платежа, поэтому аналитика относит оплату
  к дате визита.
- Пароль демо-пользователя `admin123` предназначен только для локального запуска.
